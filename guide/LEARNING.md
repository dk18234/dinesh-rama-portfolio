# Learn the portfolio from scratch

Start after the project-building phase. Take one small exercise at a time and explain what changed before moving on.

1. **HTML and CSS:** identify a heading, link, button, image, spacing rule, and responsive breakpoint. Learn what the browser receives and what CSS changes.
2. **JavaScript basics:** practice variables, arrays, objects, functions, and array filtering with three tiny project objects.
3. **TypeScript:** read the `Project` interface in `src/data.ts`. Add an optional field and see how the editor catches an incorrect value.
4. **React components:** trace one project record into its card. Learn props, JSX, conditional rendering, and mapping an array.
5. **State:** inspect the project filter and selected-project state. Change a filter label and predict which records appear.
6. **Dialogs and keyboard use:** open a project with the keyboard, cycle through its controls, close with Escape, and check where focus returns. Read the corresponding effect and cleanup.
7. **Responsive design:** open the mobile menu and compare the card grid at small and large widths. Identify the Tailwind breakpoint classes.
8. **Build and deploy:** run the root and subpath builds. Explain why `/images/photo.jpg` differs from a base-aware asset URL on GitHub Pages.
9. **Own a change:** add a useful project detail field, render it in the dialog, update the verification script if it represents a required contract, and publish it.

A good interview explanation is: “I adapted a supplied design into my engineering portfolio, modeled project content with TypeScript, integrated project demos and repositories, and added checks for complete entries and deployment paths. AI assisted the implementation; I can explain the components and changes I now own.”

Do not claim the template's design as original or invent usage metrics. Learn to explain this site and the deeper backend projects in your own words.
